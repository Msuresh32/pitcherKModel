    Anti-leakage audit: PASS — all 105 folds satisfy train_end < eval_start.

    Training period (2022-2024) vs. evaluation period (2025-2026):
      Mean K/start:  train=4.931  eval=4.916  delta=-0.015  p=0.684 (n.s.)

    improve the model by absorbing a changing environment — the environment

Finding 3: SEASONALITY, NOT MODEL AGE, DRIVES PERFORMANCE
    Variance explained in |projection error|:
      Calendar month:  29.4%  (r=+0.393, p<0.0001)
      Model age:        6.6%  (r=+0.108, p=0.0002, after controlling for month)

    Calendar month is 4.5× more important than model age.
    Win rate: calendar month explains 16.7%, model age explains 5.2%.

    Practical implication: 335-day reduction in model age (annual to monthly
    retraining) would improve RMSE by approximately +0.003 Ks/start — noise.

PRODUCTION RECOMMENDATIONS
================================================================================

IMMEDIATE CHANGES (high confidence):

  1. SKIP JULY–SEPTEMBER BETTING
     Evidence: 3-month, 386-bet dataset, p<0.00001.
     Both years of early-season data show positive ROI; July-September 2025
     (only year with data) is -8% to -16% at ANY probability threshold.
     Implementation: add `month ∈ {7, 8, 9} → reject bet` to pricing.py.

  2. RAISE MINIMUM PROBABILITY THRESHOLD TO 65%
     Evidence: discovered on 2025, validated on 2026 (p=0.0055, survives
     Bonferroni). Current filter has no minimum probability requirement,
     allowing the catastrophic 55-60% band to select bets that consistently
     lose in both years.
     Implementation: add `model_prob_over >= 0.65 OR model_prob_under >= 0.65`
     to the EGP filter in pricing.py. Keep EGP >= 6 as additional requirement.

  3. CONSIDER RAISING TO 70% (more aggressive but higher ROI)
     2026 holdout: n=86, WR=69.8%, ROI=+32.2%, p=0.0016.
     Tradeoff: fewer bets (86 vs 137 early season 2026), but higher ROI.
     Recommendation: deploy at 65% first, monitor for 1 month, then consider 70%.

MEDIUM-TERM CHANGES (moderate confidence):

  4. ANNUAL RETRAINING (expanding window, December 31 cutoff)
     The walk-forward shows no meaningful improvement from more frequent
     retraining (RMSE spread 0.019 Ks across 7 policies). Annual retraining
     is the best tradeoff of simplicity vs. marginal accuracy gain.
     Schedule: retrain each year in mid-January after the prior season's data
     is fully collected and processed.
     Command: py -3.14 scripts/train.py --config config/config_v4_production.yaml

  5. CALIBRATION CORRECTION (future improvement)
     Apply Platt scaling or isotonic regression to model probability outputs
     using OOS predictions as calibration set. Temperature scaling at T=2.5
     shows ROI improvement (+7.5% → +12.0%) in backtesting, but validation
     set is small. Requires more data before deployment.

  6. FIX IMPUTATION LEAKAGE (already implemented)
     Two-pass imputation is now in place (train.py + build_features.py).
     Retrain the model once to eliminate the contaminated model weights.
     Use: py -3.14 scripts/train.py --config config/config_v4_production.yaml

NOT RECOMMENDED:
  - More frequent retraining (Monthly, Bi-weekly, Weekly): no evidence of benefit
  - Rolling 2-year window: marginally better (0.019 Ks) but discards informative
    historical data; expanding annual window preferred
  - Automated bet placement: decision-support system only
  - Betting in June without monitoring: June is volatile (2025: +28.6%, 2026: -16%)
    due to small sample effects. Continue betting but monitor CLV closely.

MONITORING METRICS (per month):
  - Win rate: alert if < 48% over 50+ bets (2 SD below recent average)
  - CLV mean: alert if < -1.5 (closing line consistently moving against positions)
  - Projection bias: alert if mean(proj - actual) > +0.5 or < -0.5 over 100 bets
  - Model age: flag when > 400 days since last retrain (approaching next season)

EMERGENCY RETRAIN CONDITIONS:
  - CLV is consistently < -2.0 for 2 consecutive weeks (market is systematically
    outpricing the model — urgent signal)
  - Win rate < 44% over 100+ bets (extreme underperformance even accounting for
    variance)
  - A rule change affects K-rate environment (e.g., pitch clock modifications,
    enforcement changes, batting rules)
  - New pitcher population characteristic (e.g., major injury wave affects
    typical starter profiles)

SUPPORTING DATA: IMPUTATION BUG FIX DETAILS
================================================================================

BUG IDENTIFIED: Single-pass imputation in train.py was calling
build_training_features() on ALL data before splitting into train/test.
When fill_values=None (line 1296-1297 of build_features.py at time of finding),
medians were computed from the FULL dataset including test-period rows.

IMPACT: Model was trained on features imputed with future-data medians.
The fill_values saved to fill_values.json were correct for inference (computed
from train period only), but the model WEIGHTS were fit on contaminated features.

FIX IMPLEMENTED:
  src/features/build_features.py: Added return_before_impute=True parameter
  scripts/train.py: Two-pass approach:
    Pass 1: build_training_features(..., return_before_impute=True) — no imputation
    Pass 2: compute medians from train period only, apply to full dataset

ACTION REQUIRED: Retrain models using clean implementation before next deployment.

METHODOLOGY NOTES AND LIMITATIONS
================================================================================

1. SINGLE LATE-SEASON YEAR: July-September analysis is based entirely on 2025
   data (n=386). While the p-value is highly significant (p<0.00001), it's still
   one season. 2025 may have had unusual late-season K-rate dynamics.
   Recommendation: keep the late-season skip rule but reassess after 2026 late
   season data is available (October 2026).

2. PROBABILITY THRESHOLD SEARCH: The model_prob >= 65% threshold was selected
   after testing 5 thresholds. However, it was validated on the 2026 holdout,
   and p=0.0055 survives Bonferroni correction (0.05/5=0.01). The 70% threshold
   (p=0.0016) is even stronger. This is not a pure discovery-validation split
   because calibration analysis used both years — but the threshold was
   specifically discovered using 2025 data and validated on 2026.

3. BACKTEST JOIN COMPLETENESS: The walk-forward betting analysis joins on
   pitcher_id. Name-to-ID mapping achieved ~41% match rate due to name
   variations (accents, nicknames). This understates bet counts vs. the true
   backtest. The relative comparison across policies remains valid.

4. NO JULY-SEPTEMBER 2026 DATA: Late-season conclusion relies entirely on 2025.
   Cannot confirm whether the early-season success in 2026 would continue if
   betting through September.

5. OPPORTUNITY MODELS EXCLUDED: Walk-forward used only the 100 core features
   (excluded expected_innings_pitched, expected_pitches, expected_batters_faced).
   Opportunity models were not retrained per-fold for computational efficiency.
   The production model uses these features; retraining opportunity models
   annually would provide complete validation.

6. BIAS-VARIANCE IN CALIBRATION: Calibration error of -11.2 pp is measured on
   the SAME data used for betting decisions (no separate calibration set).
   True OOS calibration error may differ. However, cross-year consistency of
   the 55-60% band problem (both 2025 and 2026 show poor WR in this range)
   provides strong evidence of a real systematic effect.
